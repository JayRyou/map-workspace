# P1.6 상태 흐름

아래 상태는 디자인 시뮬레이션이며 API/로컬 저장을 수행하지 않는다. 실제 구현 책임은 D-02/P4다.

|상태|사용자 문구|예시 행동|실제 구현 조건|
|---|---|---|---|
|clean|저장됨|내용 확인|ack+후속 dirty 없음|
|dirty|변경 있음|저장 시나리오|debounce·직렬 queue|
|saving|저장 중…|후속 수정 예시→dirty|전송 snapshot만 ack|
|error|저장하지 못했어요|내보내기/같은 요청 재전송|mutationId로 결과 중복 방지|
|offline|오프라인|초안 회수/재연결→conflict|계정별 draft;최신revision 확인|
|conflict|다른 사람이 먼저 저장했어요|최신본 확인/초안 유지/내보내기/재시도/사본|409 후 초안 덮기 금지|
|revoked|편집 권한이 변경됐어요|쓰기중지/초안회수/logout|서버 현재 membership 확인|
|signedOut|계정 진입 화면|초안처리확인/logout취소|session 폐기·타계정 초안 격리|

재시도 버튼은 서버 최신본을 확인한 뒤에 활성화한다. 최신 revision을 무조건 덮어써 넣는 대신, 변경 재적용 선택을 거치면dirty로 돌아간다. 응답 유실 재시도와409재적용은 서로 다른 동작이다. 로컬 초안 유지는 P1 메모리 시나리오 표시에 한정하며 영구 보관했다고 표시하지 않는다.
