# MAP Workspace 제품 요구사항

버전 P0 제안 1.0 / 2026-10-09 / 승인 전. 범용 맵에서 요소·관계·설명·결정·업무를 함께 관리하는 SaaS다. 핵심 검증 대상은 3~4인 팀이며 개인도 같은 엔진을 쓴다. RWA 데이터는 이전 프로토타입 예시로만 취급한다.

## 문제와 가치

다이어그램과 업무 목록·결정 문서가 분리되면 관계를 이해하기 어렵고 변경 이유를 잃는다. 사용자는 맵에서 대상을 선택하고 그 이유·담당자·연결 업무까지 이어서 확인해야 한다. 작업 대시보드나 AI 채팅이 첫 화면을 차지하지 않는다.

## 사용자와 성공 기준

|사용자|주요 과업|베타 검증 가설|
|---|---|---|
|개인 기획자/학습자|아이디어를 묶고 관계와 근거 기록|가입 후 10분 내 5노드·4연결·1그룹 맵 생성|
|개발자/설계자|시스템 구성과 의존 관계·미결정 사항 확인|관련 요소와 결정 근거를 3회 이하 선택으로 탐색|
|3~4인 팀|같은 맵을 조회·수정하고 업무 배정|초대→권한→두 브라우저 저장→충돌 해결 성공|
|AI 도구 사용자|선택 범위를 안전하게 Markdown으로 이동|선택·이웃·결정·관련 업무가 정확하며 비선택 비공개 내용 미포함|

수치는 시장 성과가 아닌 검증 목표다. P1에서 대표 사용자 3~4명 사용성 점검, P9 베타에서 첫 맵 저장률/7일 내 재방문/충돌 후 복구 성공률을 동의된 비식별 이벤트로 측정한다. 본 P0에서 사용자 조사나 전환율 측정을 수행했다고 주장하지 않는다.

## 비기능 요구사항

- React+TS 정적 번들. S3+CloudFront 또는 Cloudflare static assets 가능. 인증/공용 저장/권한/과금은 별도 서버리스 API 필요. SSR·상시 Node 서버 없음.
- 모든 API에서 서버가 tenant와 역할을 검증. private project 기본값. URL을 알아도 무단 조회 불가.
- 500노드/1,000연결의 상한 내 테스트 fixture에서 선택 반응 p95 100ms, 초기 맵 표시 p95 2초 목표(테스트 장비·payload·네트워크 조건을 P2 기록). 이는 측정 전 목표다. 1MiB 저장 상한이 먼저 도달하면 크기 제한 우선.
- 서버 저장 ack p95 1.5초 목표(한국 클라이언트, 권장 리전 실측 P4). 초안은 입력 후 1초 이내 로컬 내구 저장 목표. 저장 실패와 충돌은 명시적으로 표시.
- 키보드 편집 대안, 명확한 포커스, 색 외 상태 텍스트, IME 입력 보호, 200% 확대 검증. 상세 수용 기준은 UX_PRINCIPLES.
- 일별 별도 백업 RPO 24시간/RTO 4시간은 베타 목표. P8 복원 훈련 전 보장하지 않는다.
- 서버 오류·권한 거절·충돌·백업 실패를 관측하며 본문/토큰/초대 링크를 로그에 남기지 않는다.

## 비목표와 출시 조건

AI 모델 호출·Agent 실행, 실시간 커서/CRDT 공동 편집, 채팅, 고급 간트, 모바일 네이티브, 고급 분석, 마켓플레이스는 Later. 모바일 웹은 조회와 기본 폼을 지원하되 정밀 맵 편집의 주 대상은 데스크톱이다. 출시 전 P8의 Critical/Major 0과 P9 공개 배포 승인을 모두 받아야 한다.
