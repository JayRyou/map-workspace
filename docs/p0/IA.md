# 정보 구조와 화면 책임

홈은 KPI 대시보드가 아니라 최근 프로젝트·맵으로 진입하는 작은 목록이다. 앱의 작업 중심은 맵이다. 기본 계층: 워크스페이스 → 프로젝트 → 맵. 업무/결정 목록은 같은 맵 데이터의 보조 뷰이며 별도 제품처럼 분리하지 않는다.

## 맵 화면 영역

- 상단 48~56px: breadcrumb, 맵 이름, 저장 상태, Undo/Redo, 검색, 공유. 자주 쓰는 도구만 노출.
- 좌측 200~240px: 프로젝트/맵 탐색과 요소 목록. 접기 가능하며 별도 KPI나 뉴스 피드 없음.
- 중앙: 캔버스. 도구는 노드/연결/그룹/선택으로 최소화하고 zoom/fit는 하단 한 묶음.
- 우측 300~360px Inspector: 선택 대상의 label/타입/설명/속성 → 관계 → 결정 → 업무 순서. 선택 없음이면 맵 설명/안건 요약만, 무의미한 빈 카드 없음.
- 보조 모달: 삭제 영향,가져오기 preview,공유 공개범위,충돌 해결. 편집 화면을 연속 모달로 탐색하지 않게 한다.

desktop1440px에서 기본 캔버스 가로 비중60% 이상을 P1 검증 목표로 한다. Inspector를 접으면 더 넓어진다. 390px 모바일에서는 접힌 탐색과 읽기 맵/요소 목록, 선택 상세를 전면 sheet로 제공한다. 정밀 마우스 편집과 같은 편의성을 약속하지 않는다.

## 흐름과 데이터 경계

선택 상태/viewport/필터는 개인 view preference, 노드 좌표/내용은 공유 document다. 한 사람이 필터를 바꿔도 다른 사람의 저장 revision을 올리지 않는다. 맵을 전환할 때 dirty/실패/충돌을 확인하고 초안 저장/회수 선택을 제공한다. 주소의 node/decision/task ID는 탐색 요청일 뿐 권한 우회 수단이 아니다.

로그아웃·권한회수·공유만료 화면도 정상 흐름으로 설계한다. 맵 오류를 전체 앱 빈화면으로 바꾸지 않고 재시도·최근초안·오류ID를 제시한다.
