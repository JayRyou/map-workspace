# MAP Workspace — P0 검수 요약

첨부한 작업 규칙과 P0 프롬프트에 따라 **P0-A~F 분석·설계를 완료**했습니다. 현재 상태는 **검수 대기**이며 P1 이후 구현은 시작하지 않았습니다.

## 핵심 제안

Flow Workspace의 React/TypeScript·React Flow 편집 기반과 데이터 검증 패턴을 재사용합니다. RWA MAP의 관계 탐색, 상세 맥락, 확정·미정 결정 표현은 범용 모델로 옮깁니다. 두 화면을 단순히 이어 붙이지 않습니다.

로그인 계정과 담당자 명부, 결정 상태와 업무 진행 상태를 분리합니다. 저장은 맵 단위 revision으로 충돌을 거부하고 내 초안을 보존합니다. 일반 맵은 순환 관계를 허용하고 업무 선행관계만 DAG로 제한합니다.

인프라는 **Cloudflare Workers Paid + D1 + 정적 자산**, 인증은 **Cognito Essentials 한국어 Managed Login**을 우선 권장합니다. AWS 단일 구성과 비교했고, 실제 생성·배포·과금은 수행하지 않았습니다. [한국어 Managed Login 공식 근거](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools-managed-login.html).

## 검증과 한계

- Flow: 빌드 성공, 단위17/17·브라우저29/29 통과.
- RWA: API9개 동작 확인. 잘못된 내부 데이터 수용은 결함 재현으로 기록했습니다.
- 원본416파일 변경0. 인프라/결제/운영배포 없음.
- 기존 SaaS 전환 차단 Major4를 식별했습니다. 계정 격리,JSON 검증,충돌 초안 보존,손상 저장소 복구를 후속 단계에서 해결해야 합니다.
- 실사용 RWA 담당자/배정 데이터는 없어 실제 데이터 이관은 미검증입니다.

자체평가 **94/100, CONDITIONAL**. 사용자·별도검수자의 승인과는 다릅니다. 필수문서25개와 계산/테스트 증거를 제공했습니다.

## P1 및 승인할 사항

P1은 실제 제품 리서치 보강,IA·한글 용어·디자인 토큰,1440/390px 와이어프레임,선택/저장실패/충돌/공유/가져오기/내보내기 상태를 설계합니다. 프로덕션 맵 엔진·인증·서버는 P1 범위가 아닙니다. P1_SPEC.md에 세부 작업과 완료 기준을 정리했습니다.

검수할 결정은 ①MVP 범위와 공통 데이터 모델 ②Cloudflare+Cognito 권장 방향 ③맵 단위 충돌 해결과 공유 정책입니다. 가격·리전·도메인·실결제는 해당 후속 페이즈에서 확정합니다.

상시 작업 규칙과 P0 프롬프트에 따라 **P0 검수 승인 후에만 P1을 시작**합니다.
